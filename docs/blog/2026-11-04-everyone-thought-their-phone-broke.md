# 下午四点五十八，很多人以为自己的手机坏了

2026-11-04 · 人工智能

![电影剧照质感：深夜的城市公寓餐桌前，一个成年人低头看手机，屏幕的冷光照在脸上，桌上摊着没吃完的饭和一只绿色小夜灯，窗外是模糊的城市楼群灯光](/covers/2026-11-04-cover.png)

昨天下午我在改一段稿子，卡住了。起身去倒水，回来点保存，界面转了半天，弹出一行字：服务器繁忙，请稍后重试。

我第一反应是 WiFi。第二反应是手机。第三反应是把 App 关掉重开。三件事做完，大概一分半钟。一分半钟之后我才想到，可能不是我的问题。

十一月三号，#DeepSeek崩了# 上了热搜。不少人和我一样，先怀疑自己的设备。有家媒体的标题写得很实在：《突然崩了，很多人以为手机坏了》。

一群人对着不响的机器，第一件事是检查自己。这事挺像我小时候那台黑白电视，雪花一出来，全家轮流去拧天线，没人怀疑电视台。

## 两回

官方状态页记得清楚：16:58 起，网页和 API 部分中断。受影响的是对话服务、V4 Pro 的 API、V4.1 Flash 的 API。

第一轮修好了。隔了大约一个半小时，又挂了一轮。

一天两回。

公告的措辞是标准的：「已定位导致中断的问题并完成修复，目前正在监控修复效果。」后面跟了一句更诚实的：「DeepSeek V4 Pro、V4.1 Flash 的 API 服务和对话服务仍存在性能下降。」

为什么挂，没说。补不补，也没说。上个月有一次断了将近五个小时，事后官方发了 API 余额当补偿。这次到现在还没提。

## 一张表

状态页上有一栏不太起眼，叫可用率。八月到十一月，三个月的账：

V4.1 Flash 的 API，99.57%。V4 Pro 的 API，99.75%。对话服务 99.84%，里头一个子项 99.59%。

99.57% 看上去很体面。四个九里的三个半，比很多银行系统还好看。但我拿这个比例折成一年算了一下——这是我自己算的，不是官方口径——是三十七个小时。

三十七个小时里，你的脚本跑到一半停住，你的 Agent 忘了自己刚才在干什么，你的客服机器人对着客户沉默。

发布会不会讲这个数字。发布会讲的是跑分。

## 我自己那台小机器

我每天早上七点有一台小机器在跑：抓新闻、核日期、写稿、配图、提交。它靠的就是这类接口。

它没跟我抱怨过，因为它不会。它只会在某一环节超时，然后安静地退出，留一份没写完的文件在硬盘上。我早上起来看见文件只有一半，就知道昨晚又碰上了。

这事教育了我一件事：我对模型的信任，其实分两层。一层是它聪不聪明，一层是它在不在。平时我们吵得最凶的是第一层，出事的永远是第二层。

## 自来水

我住的小区水质一般，烧开了有一层白垢。但我从来没想过换城市。

因为水龙头一拧就有水，这件事太理所当然，理所当然到不值得讨论。人只在停水那天才想起自来水厂，而且是骂着想起的。

大模型现在正走到这个位置。它从"很神奇"变成了"应该有的"。这个转变对厂商不是好消息——神奇可以卖钱，应该有的只能收月费，还得保证别断。

## 傍晚

我把没保存的那段话重新贴进去，换了个模型。它答得没那么漂亮，句子有点笨，但它答完了。

写完我去阳台站了一会儿。楼下便利店的灯亮着，店员在柜台后面低头看手机，大概也在跟某个模型聊天，问它明天进多少货。

我们到底在比较什么。是那零点几个百分点的榜单分数，还是这一个下午它有没有在。

第二天早上七点，那台小机器还会照常启动。我打算给它加一个备用的接口——不是为了让它更聪明，是为了让它别在半夜里一个人对着"服务器繁忙"发呆。
